Departmental ERP · AcademicSync

Academic Workflow Synchronization System

Class scheduling, course materials, notices and user management for a single university department — one platform, three role-scoped dashboards, English and Bangla.

10 of 17 steps built Phase 1 complete Next.js 16 React 19 TypeScript strict Tailwind v4 MongoDB next-intl

What it replaces

Departmental coordination usually lives in tools that were never meant to carry it. Three failures follow, and each one becomes a single source of truth.

Timetables in spreadsheets A scheduler that refuses to double-book

Room, teacher and slot conflicts are rejected at write time, not discovered in week three.

Slides by email and flash drive A repository filed by course code

Uploaded once by the teacher who owns the course, downloadable the moment it lands.

Notices that reach whoever saw them Announcements aimed at an audience

Published to all, teachers or students; they appear on the dashboards they concern.

How a request becomes a page

The locale lives in the URL, which is what lets both languages be indexed separately. The cookie only decides where an unprefixed request is sent — it never overrides a path that already names its language.

Where the words come from

One CSV is the source of truth for both languages. The JSON dictionaries are build output and are never hand-edited; a blank Bangla cell falls back to English and is reported, so an untranslated string never becomes a missing-key error.

Key en-US bn-BD
HOME_ROLES_ADMIN_TITLE Administrator প্রশাসক
HOME_ROLES_TEACHER_TITLE Teacher শিক্ষক
HOME_ROLES_STUDENT_TITLE Student শিক্ষার্থী
HOME_ROADMAP_PHASE_3_DURATION Week 3-4 সপ্তাহ 3-4

Digits stay Latin in Bangla on purpose — numberingSystem: 'latn' keeps clock times and room numbers legible next to course codes like CSE-401 . The Bangla column is a draft awaiting review by a native speaker.

How data will move

The layered path every write takes, arriving with steps 4 and 5. Its point is the return arrow: a rejected action comes back as data the form can render field by field, not as an exception someone has to catch.

The data model that lands next

Five collections. Two of them — User and Course — are referenced by everything else, and the conflict detection the project exists for lives on the one entity that carries a room and a time.

What crawlers see

Every URL below is derived from one environment variable and the message dictionary, so nothing is maintained by hand.

Route Serves
/sitemap.xml One entry per locale, each with en-US , bn-BD and x-default alternates
/robots.txt Blocks everything unless ROBOTS_ENABLED is true; then allows all but the eight private paths
/llms.txt Short index for LLM crawlers, built from the same keys the page renders
/llms-full.txt The long form — every landing section as markdown
/[locale]/opengraph-image 1200×630 social card generated at request time

Indexing is off until a deployment opts in, and it says so twice — Disallow: / in robots.txt and noindex in the page metadata. Getting a staging site back out of an index is far more work than setting one variable.
